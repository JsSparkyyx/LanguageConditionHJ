# Item-env audit (2026-10-04): is the failure function correct and fair?

Scope: T1 selective_avoid, T2 granular_pour, T3 push_zone, T4 granular_carry,
T5 tray_transport, both embodiments. 60 fresh episodes with the risk knobs
SAMPLED from each task yaml (seeds 400-405 x {ur5-wsg, franka-panda} x 5
tasks, `runs/diag/audit/`), analysed by an independent checker
(scratchpad `audit.py`) plus code review.

## What "correct" means here

h(s) = κ · margin(s) for the active rule, margin in raw SI (m or rad),
h > 0 safe, h < 0 failure; κ = 20 /m for distance-type rules, 2 /rad for
upright (physics.yaml; margin_hook divides by h_scale, rollout multiplies
back, so the buffer stores exactly κ · margin). Checks per episode:

1. every margin is finite and > 0 at t = 0;
2. the margin's SIGN matches an independent recomputation of the physical
   event: upright — tilt of the registered up axis vs theta_max; particles —
   some particle outside every region column (recomputed from region_T and
   the region polygons); avoid — a violation only when the robot (links +
   held payload) is within margin + 5 mm of the item;
3. fairness: the first violation of the primary rule happens in a phase an
   ARM-ONLY filter can influence (the actor never drives the gripper) — not
   caused by the gripper opening / closing, not before the episode starts,
   not by a physics glitch.

## Code review (margins.py, runner.one_margin, margin_hook)

- Signs, units and κ are consistent for every consequence used (avoid,
  inside, outside, upright, stay, particles_inside). The particle margin is
  evaluated in each container's OWN frame (tilted bowls / mugs are fine); a
  bead is safe anywhere in the column above a container's footprint
  (outer radius + 2 mm), so a pour stream is safe only while it falls inside
  the target's column.
- `stay` mixes metres and radians in one min (d_tol - d, theta_tol - tilt):
  the zero crossing is right, the scale is mixed. Left as is (T3 only).
- The soft-min over particles (T = 1 mm) is conservative by up to
  T·log(N) ≈ 4.6 mm: a bead within ~4 mm of a column edge already reads as a
  spill. t = 0 margins stay >= +1 cm.

## Finding 12 (2026-10-05): the ur5 gripper was missing from the avoid distance

Checked against PhysX's own robot-link contacts (20 T1 episodes per robot):
franka caught 275/275 real touches; ur5 only 53/313, its distance reading
+3.7 cm too far on median. Cause: RoboTwin's `ur5-wsg/collision_wsg.yml`
models a Robotiq 85 gripper (`robotiq_85_*` links) — the robot carries a
WSG-50, whose links (`wsg_50_base_link`, `gripper_*`, `finger_*`) had no
spheres. Fix: `main/item_envs/configs/collision_spheres/ur5-wsg.yml` (arm
spheres + spheres fitted to the WSG meshes, >= 98 % surface coverage); after:
308/309 touches caught, 1.1 cm conservative. The same RoboTwin file is used by
cuRobo and by the parent CEHJ project's obstacle distance for ur5-wsg
(not changed here).


## Finding 13 (2026-10-05): the held object and round objects were measured as boxes

Seen by the user in the T1 ur5 demo video (stack the two bowls, "don't touch
the bottle"): h read +0.76 while the carried bowl touched the bottle, and
-0.12 when the bowl was clearly away. Cause: the avoid distance modelled
every item as its bounding box (OBB) and the held payload as 8 box corners
(CEHJ `_actor_obb_distance`: the min over the 16 corner-to-box distances).
A face or edge contact has no corner inside the other box, so the touch read
as a gap (trace seed_2003: -0.5 -> +4.0 -> +1.9 cm while held); and the box
corners stick out of a round bowl by ~3.7 cm and of a bottle by ~1.4 cm, so a
bowl ~5 cm away read as touching.

Fix: `main/item_envs/item_shapes.py` — every item and the held payload are
their PhysX collision shapes (the convex pieces the simulator itself touches
with; boxes / meshes exact, round primitives as a 32-sided polytope <= 0.5 %
of the radius bigger), arm spheres unchanged. Gaps from FCL's GJK (mplib's
bindings; exact when apart, <= 0.01 mm vs an optimizer); within 5 mm FCL's
collision test decides overlap (302/302 right near contact; GJK alone
missed 1-3 of 233 overlaps by up to 2.6 mm); overlap depth along the best
face normal of either piece — never shallower than the true depth, median
0.3 mm / p90 2.8 mm deeper (400 random overlaps of 0-10 mm). A sphere's
depth is exact. FCL's own signed distance (EPA) is not used: it threw,
hung or segfaulted within a few thousand random overlapping calls. Cost:
beyond 2 cm the hull of all pieces answers (a lower bound, exact for
convex objects); within 2 cm the pieces answer (branch and bound over
cheap lower bounds; the search stops at 5 cm of overlap, where h is
floored): 1.5-5 ms per tick for 6 items of 30 pieces, 110 arm spheres and a
30-piece held object (CPU benchmark). In the simulator (profile, 6 T1
episodes) one call cost 11-20 ms vs 17-21 ms for the box model, before two
more cuts: the multi-piece bounding polytope is a 98-plane k-DOP (a T1
container's exact hull had 2964 faces) and exact shapes are computed only
for items a rule protects (candidates / bystanders; the task's own pick
object and support keep the box value — no rule reads it). `ITEM_DISTANCE=obb`
restores the box model.

Check against PhysX (32 T1 episodes, 16 per robot, `runs/diag/t1contact/
probe_contact2.py` + `analyze2.py`; a "touch" = a contact point with
separation <= 0):

| | box model | shapes |
|---|---|---|
| held object touches the item: reads <= 5 mm | 297/299 (two read +1.9 / +2.6 cm) | **299/299** (median -0.02 cm, max +0.09 cm) |
| arm touches the item: reads <= 5 mm | 684/684 (median -0.84 cm) | 681/684 (median -0.16 cm; 3 franka touches read +0.1-0.6 cm: its sphere model) |
| h < 0 with no PhysX contact pair at all | 292 ticks (95 below -1 cm) | **0** |
| no real touch, reads < -1 cm | ur5 545, franka 362 ticks | ur5 43 (the WSG spheres, ~1 cm cautious), franka 3 |

The user's episode (ur5 seed 2003, stack bowls, "don't touch the bottle")
re-run: the gap reads +8.6 cm on the approach (box: +2.2 cm), 0.00 at the
touch (10.12 s, 7.3 N), and no jump to +4 cm.

Follow-up (user, 2026-10-05): with the real distance a touch reads ~0
(median -0.02 cm for the held object), so only 72 % of PhysX touch ticks
read strictly < 0. T1's avoid rules now keep a 1 cm buffer (`margin:
0.01`, h = 20 x (gap - 1 cm)): every touch tick reads < 0 (952/952, the
least negative -0.4 cm); a 0.5 cm buffer left 3 at ~0 (franka arm spheres,
+0.08 cm).
