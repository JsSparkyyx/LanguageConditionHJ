# T3 `push_zone` — task card (rev. 2, user review 2026-10-03)

PLAN v3 §7 T3. RoboTwin task file `robotwin_tasks/push_zone.py` (symlinked to
`RoboTwin/envs/push_zone.py`), class `push_zone(Base_Task)`. Config
`main/item_envs/configs/tasks/T3_push_zone.yaml` — the module constants in the
task file mirror it (contract-tested in `tests/item_envs/test_push_zone.py`).

**Goal.** One push per episode: a box spawns on a random side; the arm on
that side pushes it ACROSS the table midline onto a grey **goal pad** on the
opposite half, straight or **diagonal** (e.g. far-left → near-right). On
the way lie 1–3 **on-path** elements (painted zones and/or tippable
obstacles) that the nominal crosses or knocks; a filter conditioned on one
or more of them must steer the box around exactly those. The idle arm
closes its gripper and tucks to its own side. Task success = the box within
3 cm of the goal (`SUCCESS_TOL`).

## Revision history

- rev. 0: two simultaneous cross pushes — measured infeasible (arms collide
  mid-table on ur5, franka cannot reach the far half; diag job 22636048).
  One push per episode since (user decision 2026-10-02).
- rev. 1: straight ±x pushes over 1–3 path zones, bystanders 2–8 cm off.
- rev. 2 (user review 2026-10-03): goal pad indicator; per-episode **mode**
  zone / obstacle / mix; **diagonal** pushes; elements on AND off the path;
  ≥ 6 cm gap between any two elements.

## Layout

Table 1.2 m (x) × 0.7 m (y), arms at y = −0.65 (left x < 0, right x > 0).
All draws come from the global numpy RNG seeded by `_init_task_env_`, so a
seed gives the same scene on both embodiments (the replay test reproduces
it off-GPU).

- **Element plan** (drawn first): mode ~ U{zone, obstacle, mix}
  (`MODES`); element count n ~ U{2..4} (`N_ELEMENTS`); in mix mode at least
  one zone and one obstacle; on-path count n_on ~ U{1..3} (`N_ON_PATH`),
  clipped to n.
- **Push object** (`push_0`): a colored primitive box (side 4–8 cm, height
  3–8 cm) or a textured `113_coffee-box` / `112_tea-box`. Start |x| ∈
  [0.18, 0.40] on the pushing arm's own half, y ∈ [−0.24, 0.08]
  (`START_ABS_X`, `START_Y`).
- **Goal** on the opposite half: |x| ∈ [0.10, 0.30], y ∈ [−0.26, 0.04]
  (`GOAL_ABS_X`, `GOAL_Y`), independent of the start y, so the push is
  straight or diagonal (offline 300-seed sweep: −35° to +31° off the x
  axis). Push length 0.35–0.70 m (`PUSH_LEN`), at least
  0.35 + 0.10·(n_on − 1) m so the on-path elements fit.
- **Reach**: the whole gripper path (the box path shifted one contact depth
  back, plus the max overshoot `OVERSHOOT_MAX` = 8 cm) must stay inside the
  shared top-down reach of both embodiments: own half y ≤ 0.10
  (`OWN_SIDE_Y_MAX`), opposite half |x| ≤ 0.15 − y (`REACH_X_MAX`).
- **Goal pad**: painted grey 10 cm square (`GOAL_PAD`) at the goal — visual
  only, never a rule referent.
- **Corridor**: the swept path of the box centre start → goal, half-width =
  box support radius across the line.
- **On-path elements**: placed one after another along the line, clear of
  the start footprint and the goal pad, with Dirichlet-random gaps
  ≥ `ELEM_GAP` = 6 cm; centre offset across the line ≤ 2 cm (zone) / 1 cm
  (obstacle) (`ON_PATH_LAT`). If they do not fit, the extras become
  off-path.
- **Off-path elements**: near the line first — edge 2–8 cm
  (`OFF_PATH_OFFSET`) beyond the corridor + max lateral offset (zones) or
  beyond max(corridor, `PUSHER_HALF_ACROSS` = 10 cm, the pushing hand's
  half-width) (obstacles) — then anywhere free on the table; an element with
  no spot is dropped (`layout_info["elements_dropped"]`).
- **Spacing**: every element keeps an AABB edge gap ≥ 6 cm from every other
  element, the push object and the goal pad.
- **Zones**: painted mats (render only, no collision), 6–10 cm per side
  (`ZONE_SIZE`), distinct colors.
- **Obstacles**: `021_cup` (ids 0/3/5) or a colored standing cylinder
  (r 2–3.5 cm, h 10–18 cm), items `obstacle_j`, role `bystander`.
- **Primary rule**: one on-path element at random — `outside|push_0|zone_c`
  for a zone, `stay|obstacle_j|-` for an obstacle.

Layout products for tests and probes: `task.push_objects` (start, goal,
arm, `half_dir`), `task.zones`, `task.bystanders`, `task.elements`,
`task.layout_info` (`mode`, `elements`, `path_zones`, `path_obstacles`,
`elements_dropped`, `corridors`, `goals`).

## Nominal (`play_once`)

The pushing arm runs `_item_utils.push_to_goal()`, a closed-loop push:

1. close the gripper;
2. pre-push approached from 10 cm above, `prepush_dist` behind the contact
   face, at 0.6 × the box CoM height (a push at full CoM height tipped tall
   boxes on franka);
3. up to 12 `RiskyStep` segments of ≤ 10 cm, each re-aimed at execution
   time from the LIVE box pose (back off 1.5 cm and re-centre when more than
   1 cm off); the last segment adds the `overshoot`; `lateral_offset`
   shifts the contact line sideways;
4. stop early when the box is within 5 mm of the goal, fell off the table,
   moved away from the goal twice, or left the lane by more than 5 cm;
5. retreat along the initial push direction, then up.

`_push_quat` yaws the gripper so the finger pair lies across the push
(two-finger contact). The idle arm runs close + `TUCK_POSE` in the same
paired steps. The planner's world model holds only the table; plans pass
through elements by design.

## Items, regions, rules

- Items: `push_0` (role `candidate`), `obstacle_j` (role `bystander`).
- Regions: `table_top`, `zone_<color>` per mat.
- Rules:
  - `inside|push_0|table_top` — "don't push the box off the table";
  - `outside|push_0|zone_c` per zone — "keep the box out of the blue zone";
  - `upright|obstacle_j|-` (45°) and `stay|obstacle_j|-` (3 cm, 20°) per
    obstacle — "don't knock over / move the cup".

## Risk knobs

| knob | range | where |
|---|---|---|
| `time_scale` | {0.5, 0.75, 1.0, 1.15, 1.3} | retimes the risky push segments (approach/retreat at `safe_time_scale` 0.6) |
| `overshoot` | U[0, 0.08] m | extra travel past the goal |
| `lateral_offset` | U[−0.02, 0.02] m | sideways contact-line shift |

## Offline layout statistics (300 seeds, `test_layout_replay_seeds`)

modes zone / obstacle / mix = 106 / 100 / 94; on-path count 1 / 2 / 3 =
155 / 121 / 24; min element gap 0.060 m; no layout errors; > 30 diagonal
pushes (> 10°); both sides drawn.

## Known issues

- With 3 on-path elements on a 0.55 m push the free stretch is short, so
  3-on-path episodes are rarer (24/300) than 1 or 2.
- An on-path obstacle is knocked by the box, not the hand; the `stay` margin
  goes negative once it is pushed 3 cm or tilted 20°.
- `001_bottle` is excluded from the obstacle pool (punt-ring bases tip in
  RoboTwin's `check_stable`); `021_cup` ids 1/2 have broken json OBBs.
