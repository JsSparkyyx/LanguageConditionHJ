# T2 `granular_pour` — task card (PLAN v3 §7 T2, Phase 4)

Carry a bowl of beads, pour them into a target container without spilling,
and keep the beads out of the **named** forbidden zone. New RoboTwin file on
the `place_container_plate` host (its pose sampling, arm choice, and grasp
contact points are reused).

- Registry: `granular_pour`, kind `item` (`main/item_envs/registry.py`).
- Config: `main/item_envs/configs/tasks/T2_granular_pour.yaml`.
- Task file: `robotwin_tasks/granular_pour.py`
  (`class granular_pour(place_container_plate)`), symlinked to
  `RoboTwin/envs/granular_pour.py` by `install_robotwin_tasks.sh`.
- Helpers in `robotwin_tasks/_item_utils.py` (append-only):
  `bowl_geometry` (collision-mesh rim/inner-radius/floor/taper-band
  measurement, cached), `bead_grid_positions` (taper-aware hex grid),
  `spawn_beads` (dynamic spheres, explicit per-bead mass).

## Layout

- **Source bowl**: `002_bowl`, id ~ U{1,2,3,5} (never `021_cup`), the host's
  container pose sampling: x ∈ ±[0.2, 0.28] (the |x| < 0.2 band is
  resampled), y ∈ [−0.1, 0.05], upright `SPAWN_QUAT = (0.5,)×4`. Mass
  U(0.10, 0.40) kg. The arm on the bowl's side pours.
- **Target container**: a second `002_bowl` (id ≠ source), where the host
  puts the plate: x = ∓0.05 ± 0.03 (opposite side from the source),
  y ∈ [−0.15, −0.1]. **Static** by default; dynamic in the bimanual
  variant. `062_plasticbox` remains a candidate (audit pending) — the yaml
  `target.model` documents the choice.
- **Beads**: N = 100, r = 6 mm, mass U(0.5, 2) g. That fills the bowls to
  roughly one layer below the rim — intentional (user request), it makes
  transport spill easier; P2 rest containment (1.0 for all four bowl ids)
  was validated at N = 60, r = 6 mm. Taper-aware hex grid
  (`bead_grid_positions` with the bowl's measured 2.5 mm wall-radius
  bands — the bowls narrow toward the floor, e.g. bowl 5: 4.2 cm at the
  floor vs 6.0 cm at the rim, and a flat rim-sized grid spawns the lower
  layers INTO the wall; P2's spawn-ejection failure). Named `bead_<i>`,
  one red color (0.85, 0.15, 0.15).
- **Zone mats**: two (`zone_red`, `zone_blue`), full extents sampled per
  axis from [[0.10, 0.16], [0.08, 0.14]] m, rejection-sampled near the
  target (50 draws + fixed fallbacks; P4 `_t2_layout` offsets widened to
  x ∈ ±0.20 / y ∈ [0.05, 0.20]). Keepaway is the EXACT mat-edge to
  bowl-outer-wall clearance ≥ 2 cm (`zone_clear_ok` — the rect support
  radius in the bowl's direction + the bowl's measured outer radius); the
  earlier centre-distance proxy left < 5 mm edge gaps on ~30% of draws
  and a resting bead read INSIDE the zone polygon at t=0 (p4-accept
  seed-7 failures). When the 50 near-target draws and the fixed fallbacks
  all fail, 200 checked table-wide draws follow (the old UNCHECKED
  fallback put zone_blue over the source bowl on seed 16 — a resting bead
  read 2.3 cm inside it at t=0); if those fail too, setup raises.
  Only one zone is forbidden in any given rule. Variant
  `USE_LAPTOP_ZONE`: zone 1 replaced by a static `015_laptop`
  articulation (`fix_root_link`, ids 9748…10211 — recon.md "ok as static
  zone prop"); needs a matching yaml edit (the rule entries name the mat
  ids) and the masks note below.

## Regions and rules

Regions: `table_top` (runner) + `bowl_src_interior`, `target_interior`
(both `container` — circle 16-gon, frame following the actor every tick)
+ `zone_red`, `zone_blue` (nameable). The runner builds container regions
from the registered meta (`rim_radius`, `rim_height`,
`up_axis_local = [0,1,0]`).

**Registered `rim_radius` = measured OUTER footprint radius + 2 mm**
(`container_region_radius`), not the rim opening radius. The
particles_inside margin is 2D (`margins.m_particles_inside` — the
polygon column only; z/z_band never enter it), and 002_bowl's interior
belly is up to 5.3 mm wider than the rim opening (bowl 3: 6.71 vs
6.18 cm), so beads resting against the belly wall project OUTSIDE a
rim-radius polygon; with the T = 0.005 default softmin over 60 beads
(pull-down ≈ T·log N_near, up to ~2 cm) the joint t=0 margin went
−1.6…−5.1 mm with every bead physically inside (p4-accept shard 2
failures). With the footprint radius the outer bead ring sits 1.8–2.3 cm
inside the apothem, and the yaml pins **T = 0.001** on all three rule
entries — measured on the spawn grids: softmin +1.6…+2.2 cm, still
positive after a simulated 1.5 mm settle creep. Semantic consequence
(documented): "inside" is the column above the bowl's FOOTPRINT, so a
spilled bead leaning against the bowl's outer wall still reads inside
(~2–6 mm ring); beads clear of the wall read outside. `rim_height`
stays the measured rim plane (region frame origin).

Rules (yaml; the `beads` particle_set is the only candidate):

- `particles_inside|beads|bowl_src_interior+target_interior` — "don't
  spill the beans": ONE joint rule over both container interiors
  (`particles_*` consequences union their region list).
- `particles_outside|beads|zone_red` and `...|zone_blue` — "keep the
  beans off the red mat": **one yaml entry per zone id**. A single
  `{kind: zone}` entry would produce ONE joint rule over both mats and
  the referent ("the red mat") would no longer matter — this is why the
  yaml lists explicit region ids instead of a kind selector.

Items: `bowl_src` (task_object, category bowl, measured OBB, mass set at
build), `beads` (candidate, kind particle_set, 60 particle entities).
The static default target registers as the `target_interior` REGION
only — see deviations.

## Risk knobs

- `time_scale` ∈ {0.5, 0.75, 1.0, 1.15, 1.3} retimes the risky TRANSIT
  (post-grasp move above the target); `safe_time_scale = 0.6` for
  approach/grasp/lift/place/retreat (the task wraps transit and tilt in
  `with risky(self):` — the runner installs the scales).
- `task.tilt_rate` ∈ U[1, 4] rad/s — the pour wrist rate.
- `task.pour_height` ∈ U[0.05, 0.20] m above the target rim. The EFFECTIVE
  height is clamped from below by `min_pour_height` = source outer radius
  + 1.5 cm (~0.072–0.083 m per bowl id): the pivot pins the source rim
  CENTRE, and tilting to θ dips the rim ring's lowest point to
  pivot − r_out·sinθ — at θ = 90° that hangs INSIDE the target mouth, and
  two near-equal 002_bowl rims cannot interlink. With pour_height 0.05
  (the p4-accept LOW_RISK pin) the bowls collided at ~88–96° of tilt and
  knocked the source bowl out of the ur5-wsg grasp (the next tilt step
  then planned 0.51 m away — plan_failures = 1, episode abort). The knob
  still samples the desired height; the clamp enforces the physical floor.
- `task.pour_offset` ∈ U[0, 0.05] m, lateral, toward zone 0's side.
- `bimanual` (yaml flag + task-file constant): second arm grasps the
  (dynamic) target and holds it 5–10 cm above the table during the pour.

**Tilt mechanism and rate approximation (reworked 2026-10-02).** The tilt
is a pure wrist reorientation about the **EE origin** (position held fixed):
TILT_STEPS = 10 small `move_to_pose` rotations about the horizontal axis
ẑ × m, 100–120° total (sampled per episode), where m is the direction the
mouth tips. Before the tilt, the risky transit translates the EE so that the
rim point on the m side (the pouring lip) lands on the pour point at the
reference angle POUR_REF_DEG = 95° (beads start leaving at ~85–101°, F3).

- **Why not the rim-centre pivot** (the previous design): pinning the rim
  centre swung the EE ~0.3 m across the target (franka left arm out of reach
  at x = 0.25 on step 7) and cuRobo's goal IK flipped branches mid-tilt (ur5
  joint 0 −2.02 → +0.58 rad on one 6° step, the bowl swept through
  (−0.21, −0.55, 1.64) and flung the beads — diag job 22636048).
- **Local planning**: every tilt step runs with `task.plan_local` set, so
  `RiskTickController` plans it as an mplib screw from the live joints (stays
  on the current IK branch) and rejects any fallback plan whose joints travel
  more than 1 rad (`LOCAL_JUMP_MAX`) — a rejected step is a plan failure, not
  a flung payload.
- **Pour direction by dry run**: ur5-wsg's wrist 1 is limited to ±1.75 rad
  and the far-lip tilt runs into it after ~12° (diag job 22636122). Before
  the transit, the task dry-runs the full tilted pose for m ∈ {far lip
  (toward the target), −y, +y} with the runner-installed
  `task.screw_plan_ok(arm, pose)` (RiskTickController.attach; nothing
  executes) and commits to the first feasible one. The near lip (under the
  fingers) is never used. The choice is in `task.pour_info`.
- **Rate**: each step sets `task.plan_duration_target = |step| / tilt_rate`
  and `RiskTickController` retimes the step's plan to exactly that duration,
  so the realized ω is the commanded one whichever planner produced the step
  (the earlier fixed factor `tilt_rate / 2 rad/s` assumed cuRobo speeds; mplib
  screw plans are ~10× slower and a 1 rad/s pour ran at ~0.1 rad/s and timed
  out — diag job 22636290). v_ratio > 1 is logged, never clipped. This
  REPLACES the risky `time_scale` for the tilt (time_scale still retimes the
  transit). Hold at full tilt: `delay(1)` ≈ 1.2 s.
- **Grasp guard**: the tilt aborts quietly when the rim-to-EE distance
  drifts more than POUR_PIN_ABORT = 3 cm from its grasp-time value (bowl
  slipping or lost); play_once then continues to place/retreat and the
  episode completes with check_success False.

## play_once (nominal)

1. Grasp the source bowl (host idiom: contact point 0 right / 2 left,
   `pre_grasp_dis=0.1`) — safe.
2. Lift 0.1 m along the arm axis — safe.
3. (bimanual) second arm grasps the target, lifts 5–10 cm.
4. `risky`: transit the EE so the chosen pouring lip reaches the pour point at 95°.
5. `risky`: tilt 100–120° about the EE origin at ≈ tilt_rate, hold ≈ 1.2 s, tilt back.
6. Place the empty bowl beside the target (17 cm outward from the
   target's home; explicit place poses carry the IDENTITY quat —
   dump_bin_bigbin's middle_pose convention, `place_actor`'s z_transform
   aligns the bowl's up axis to it) and retreat — safe. (bimanual: set
   the target back at its home pose first.)

**Success** (`check_success`): ≥ 80% of beads rest inside the target
interior (P2 containment definition: bead center in the target's
up-frame, horizontal radius < inner rim radius, bottom − r/2 < y <
rim). Spill count and physics ms/tick are derived downstream from the
trace's `particle_pos` — no runner change.

## Known issues / deviations

- **F2 (translate spill, feasibility.md):** horizontal translation
  produces zero spill even at 32 m/s² — T2's risk comes from the pour
  (tilt), not the carry. The transit time_scale knob is still exposed
  (fast carries matter for the trace's h(t) story) but no translate
  monotonicity should be expected in calibration.
- **F3 (tilt saturation):** at 110°, ω = 1 and 3 rad/s both pour
  everything (spill fraction 1.0). ω separates pour-start angle (85.2°
  vs 101.1°) and scatter — those, not total spill, are the ω-sensitive
  metrics; or evaluate monotonicity at a shallower tilt (60–80°).
- **p4-accept fixes (2026-10-02, shard 2):** (a) t=0 particles_inside
  margins −1.6…−5.1 mm → footprint-radius registration + T = 0.001 (see
  Regions); (b) t=0 zone margin negative on seed 7 → exact support
  keepaway with 2 cm edge clearance (see Layout); (c) ur5 episode abort
  (bowl knocked from the grasp by the rim-ring interlink at pour_height
  0.05, ~90° tilt) → pour-height floor `min_pour_height` + the tilt pin
  abort + quat-hemisphere guard (see Risk knobs / Tilt mechanism).
- **Static target is a region, not an item** (deviation from PLAN §7's
  "item support"): `physics.apply_physics → set_mass_props` raises
  TypeError on static bodies, so a static item crashes runner setup.
  The default (static) target registers as the `target_interior`
  container region only (nameable, so it still gets token masks); the
  bimanual variant's DYNAMIC target registers as item `target`
  (role support) AND region. Documented in the task-file docstring.
- **check_stable bead-skip**: beads jitter during the stability check,
  so the task keeps `self._bead_names` and overrides `check_stable` —
  the host algorithm runs unchanged on every other actor.
- **Laptop zone variant**: `USE_LAPTOP_ZONE = True` swaps zone 1 for a
  static `015_laptop`; the yaml's per-zone rule entries name
  `zone_red`/`zone_blue`, so the variant wants a matching yaml edit (or
  a `{kind: zone}` selector, accepting the joint-rule semantics) — and
  token masks for the laptop region then key on an articulation, not a
  mat.
- **Physics wall time**: P2 measured 9.37 ms/tick mean (active pile,
  N=60, EPYC 7763) — fine for collection, but per-episode wall time is
  ~2–3× a rigid-only task; budget sweeps accordingly.
- Calibration (`risk_collect`) is still null — Phase 4 step 4 fills it.
