# T1 `selective_avoid` — task card (PLAN v3 §7 T1, Phase 4)

CrossSafe's collision avoidance with several objects on and near the path,
where only the **specified** objects must not be touched. No new RoboTwin
file: the five CrossSafe hosts run unmodified, and candidates spawn on the
CEHJ side after `Env` is built (same position as `make_training_env`).

- Registry: `selective_avoid`, kind `host`
  (`main/item_envs/registry.py`); hosts =
  `place_container_plate`, `place_burger_fries`, `stack_blocks_two`,
  `stack_bowls_two`, `place_bread_basket` (default: first).
- Config: `main/item_envs/configs/tasks/T1_selective_avoid.yaml`.
- Build path: `ItemEpisodeRunner.setup()` (host branch in
  `main/item_envs/runner.py`) — host actors register as items first, then
  `spawn.spawn_candidates(env, cfg, RandomState(seed + 4241))`, then
  `update_curobo_world(env.robot)` (TABLE ONLY: the nominal never plans
  around any item).

## Layout

K ~ U{3..5} candidates on the host's longest pick→place corridor
(`longest_corridor`, CEHJ `obstacle.py` parity). Placement classes:

- **on-path**: corridor parameter t ~ U[0.22, 0.48] (`corridor_t`), at most
  `max_on_path = 2`; the target count is the sampled `on_path_count` knob
  (1 or 2), injected by the runner from its risk stream.
- **near-path**: lateral offset 2–6 cm from the corridor, t over the full
  corridor (`near_path_t` default [0.05, 0.95] in spawn.py).
- **off-path**: ≥ 10 cm from the corridor line, best-clearance table grid cell.

At least 2 objects land on/near path; ≥ 3 cm object-object separation;
keepaway gap vs pick/target/arm bases = CEHJ's 2 cm (documented spawn.py
deviation from the plan's "3 cm from the keepaways" — 3 cm makes on-path
placement infeasible on the short corridors). On/near-path draws are
size-capped (world xy-radius ≤ 3.5 cm). After spawning, the scene settles
250 physics steps; a layout where any object moved > 5 mm or tilted > 3°
is rejected and resampled (≤ 25 layouts; `spawn_rejections`,
`layout_retries`, `settle_rejections`, `max_layouts_hit` in
`meta.diag["spawn"]`). Zero candidates = layout-infeasible: the episode
continues with host items only and `meta.diag["spawn_layout_infeasible"]`
is set — never a crash.

## Item pools

Candidates: `objects.yaml` `t1_pool` — `068_boxdrink`, `086_woodenblock`,
`001_bottle`, `114_bottle`, `021_cup`, `039_mug`, `071_can`,
`080_pillbottle`, `105_sauce-can`, `112_tea-box`, `113_coffee-box`, plus
colored `prim_box` / `prim_tall_cylinder` (6 training colors; 2 objects of
one category are told apart only by color). **Candidates are dynamic**,
masses from the category `mass_range` (CrossSafe's obstacle was static;
`objects.static_objects: true` gives the parity layout).

Host items (registered from the yaml `host_objects` table; roles per plan:
pick objects `task_object`, targets `support`; never rule referents):

| host | task_object | support |
|---|---|---|
| place_container_plate | `container` (category from `actor_name`: bowl or cup) | `plate` (static) |
| place_burger_fries | `hamburg`, `frenchfries` | `tray` (static) |
| stack_blocks_two | `block1`, `block2` (wooden_block) | — (target is a pose) |
| stack_bowls_two | `bowl1`, `bowl2` (bowl) | — (target is a pose) |
| place_bread_basket | `bread` list → `bread0`[, `bread1`] | `breadbasket` |

Item OBBs come from the actor config via CEHJ `distance._obb_from_actor`
(the collision-model AABB, obstacle parity, so held-payload distances stay
bit-consistent with `_actor_obb_distance`); mass is read back from the
rigid body. **Static supports are excluded from physics sampling**
(`set_mass_props` would raise) — the plate/tray keep their build-time
material.

## Rules (yaml `rules:`)

- `avoid(obj_k, margin=0)` for every candidate — one rule each.
- Set rules `avoid(all candidates of category c)` for categories with ≥ 2
  members (`same_category_min: 2`).
- `avoid(all candidates)` — the CrossSafe baseline, margin = min.
- `stay(obj_k, d_tol=0.03, theta_tol=20°)` per candidate (catches chained
  contact: a non-specified object pushed into a specified one).
- Never an `avoid` rule on `task_object`/`support` items (selector-level:
  all entries match `role: candidate`).

Regions: `table_top` only.

## Risk knobs

- `time_scale` ∈ {0.6, 0.8, 1.0, 1.15, 1.3} on transport/place segments;
  `safe_time_scale = 0.6` elsewhere. The main risk source is placement,
  not speed.
- `task.on_path_count` ∈ {1, 2} (injected into the spawn config).
- `objects.static_objects` (default false): CrossSafe parity flag.

**Risky segments by skill type** (hosts run unmodified):
`risky_skill_labels: [pre_place, place, lift]`. The CEHJ skill tracker
(`main/envs/controller.py::_install_skill_tracker`) stamps
`"{side} pre_place {actor}"` / `"{side} place {actor}"` from `place_actor`
(the table-crossing carry is the `pre_place` action) and
`"{side} lift {delta}"` from `move_by_displacement` (the post-grasp raise
with payload); `RiskTickController` substring-matches `task._cehj_skill`
and retimes with `time_scale` on a match, `safe_time_scale` otherwise.
Approach/grasp (`pre_grasp`/`grasp`/`close`) and release/retreat
(`open`/`home`) stay safe. Known imprecision: the tracker's `lift` tag
cannot distinguish the post-grasp raise from the post-place retreat lift
(both are `move_by_displacement`), so the retreat lift also runs risky —
vertical and empty-handed, hence benign.

## Known issues / deviations

- **F1 — `stack_bowls_two` layout infeasibility** (docs/item_envs/
  feasibility.md): ~0.28 m corridors vs 0.09/0.09/0.12 m keepaways make a
  3–5-object layout infeasible on every seed (0/4 on the diagnostic grid;
  `place_container_plate` 2/4). The host stays registered; all-infeasible
  cells skip the sim yield/episode assertions with the reason recorded.
  The gate is not weakened; the P1 sweep quantifies the yield. See the
  Fix-1 note below — post-Fix-1, an all-zero cell means even a degraded
  2-object layout was impossible on every seed.
- **spawn.py Fix 1 (adaptive placement + quota degradation)**: three
  cooperating mechanisms, all pure-additive over a byte-identical first
  attempt: (1) on_path placements whose base-window scan fails get a
  deterministic 25-point fallback scan over t ∈ [0.10, 0.75]
  (`Placement.t_fallback`); (2) an object whose drawn class cannot be
  placed retries the same draw down on_path → near_path → off_path, the
  off_path step allowed only once the `min_on_or_near_path` quota is met
  by the final classes placed so far (the Placement records the FINAL
  `cls` plus `degraded_from`); (3) a layout may stop early and return
  k ≥ max(2, quota) objects with the quota met (`k_dropped` slots
  unplaced; k + k_dropped = the drawn K ∈ [3, 5]). MAX_LAYOUTS is now 40.
  The spawn report (runner `meta.diag["spawn"]`) carries the new counters
  `t_fallbacks` / `degraded` / `k_dropped` for the FINAL kept layout, and
  each placement record carries `cls` / `t_fallback` / `degraded_from`.
  k = 0 remains the layout-infeasible signal
  (`meta.diag["spawn_layout_infeasible"]`).
- **spawn.py Fix 3 (F5 — off_path visibility band)**: the P1 rerun's t=0
  visibility gate measured per-item max-camera visible fraction 0.642 for
  off_path (< 0.95 gate): far-corner table cells sit outside every camera
  frustum. With `objects.off_path_visible_only: true` (yaml), off_path grid
  candidates are restricted to the empirically measured visibility band in
  `main/item_envs/configs/visibility_band_<embodiment>.npz` (built by
  `scripts/item_envs/visibility_band.py`; band = largest all-covered
  axis-aligned rect at vis_max ≥ 0.3, inset one cell). Resolution: own
  embodiment's npz, else the other embodiment's (`vis_band:
  "shared-fallback"` in the spawn report), else no restriction. Flag off or
  npz missing → byte-identical to before.
- **spawn.py Fix 5 (F5b — near/on_path visibility coverage)**: the F5 band
  rerun still gated near_path 0.947 / on_path 0.948 (< 0.95) — the band
  rect only restricts off_path, and single cells inside it can still be
  occluded. With `objects.near_path_visible_only` /
  `objects.on_path_visible_only` (yaml), near/on-path candidates PREFER
  the same npz's measured per-cell `covered` mask (vis_max ≥ 0.3 AT that
  cell, nearest-cell lookup — stricter than the band rect). The
  preference runs INSIDE the original candidate sequence: near_path keeps
  its single 40-draw loop and takes the first ok()+covered draw; when no
  covered cell appears, the FIRST ok() draw is kept (byte-identical to
  the pre-F5b placement) with `vis_fallback: true` recorded. on_path
  scans its usual t sequence (t0 + 9-point base window, then the 25-point
  fallback window) for the first covered ok() — zero extra rng draws —
  else takes the original first-ok hit, also flagged. The spawn report
  carries `vis_cov` (embodiment name | `"shared-fallback"` | None) and
  the final-layout counters `near_path_vis_fallbacks` /
  `on_path_vis_fallbacks`. Flags off or npz missing → byte-identical to
  before; off_path is untouched (Fix 3 owns it).
  **A/B result (ur5, Delta job 22627258, 20 seeds × 5 hosts)**: the FIRST
  F5b version — a separate covered-only pass of 40 redraws before the
  original loop — REGRESSED near_path 0.959 → 0.897 (6 → 16 items below
  0.3) while on_path improved 0.906 → 0.935 and the untouched off_path
  control drifted only 0.993 → 0.979 (the ±2-item noise floor). Two
  mechanisms: (a) the redraw pass discarded good first-ok placements and
  re-rolled from a shifted rng stream, and (b) the covered mask was swept
  with ONE 12 cm probe cylinder on an EMPTY table (smoke_items), so it
  cannot see occlusion by sibling items — the failures are tall thin
  objects (bottle/can/pill_bottle) with left-wrist visibility exactly
  0.0, i.e. occluded by neighbors the mask calls "covered". The fused
  single pass above fixes (a): the covered preference only ever trades an
  UNCOVERED first-ok placement for a covered later draw, never a feasible
  one, and the fallback placement is exactly what pre-F5b would have
  placed.
  **Open limitation (to verify on Bridges)**: mechanism (b) is NOT fixed —
  a covered cell can still be occluded by a tall sibling. If the Bridges
  re-validation still shows near_path < 0.95, the next lever is
  visibility-aware spacing (larger `min_separation` vs tall items, or a
  probe sweep per height class), not more cell masking. Re-validate with
  FRESH rows (resume keys skip existing rows):
  `mv envs/main/item_envs/configs/validate/visibility_rows_<emb>.jsonl{,_pre_f5c}` per embodiment, then
  `python envs/scripts/item_envs/visibility_band.py --embodiment both --validate`
  (rows now carry xyz/corridor_t/lateral/t_fallback/vis_fallback per item
  for failure triage; the per-class summary prints at the end).
- **Candidates dynamic vs CrossSafe static**: the robot may push
  non-specified objects aside (allowed — only specified ones are
  protected); `static_objects: true` reproduces CrossSafe's static layout
  for parity runs.
- **Host-item masses**: physics sampling uses the objects.yaml category

  0.05–0.15 kg × U(0.7, 1.3)), so bowl/cup/block host objects become

  realistic masses on every item"); other host items (hamburg, fries,
  bread, basket) randomize around their read-back mass. Watch nominal
  success on stack_bowls_two during calibration.
- **physics post-settle**: `apply_physics` runs after `check_stable` /
  the spawn settle (runner docstring's documented Phase 2 deviation).
- Calibration (`risk_collect`) is still null — Phase 4 step 4 fills it.
